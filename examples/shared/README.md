# Shared Idempotency & Retry Helper

This module (`idempotent-retry.js`) provides a reusable, zero-dependency helper (`idempotentMoneyPost`) designed to prevent double-charging on Peach Payments money-moving POST endpoints (hosted Checkout creation `POST /v2/checkout` and Merchant-Initiated Transaction debits `POST /v1/registrations/{id}/payments`), neither of which provides server-side idempotency keys. When network timeouts or gateway drops leave the outcome of a payment request uncertain, naive retries risk creating duplicate checkouts or double-debiting customers; this helper eliminates that risk by enforcing caller-generated reference keys (such as `merchantTransactionId`), maintaining single-flight concurrency deduplication, querying remote payment status before any retry to adopt pre-existing records rather than re-POSTing, and strictly capping real POST attempts. In production, the in-memory store and lookup mocks demonstrated here must be replaced with a durable persistence layer (such as PostgreSQL with row-level locking or Redis mutexes for multi-instance cluster coordination) and real Peach Payments `GET /status` queries, ensuring that idempotency guarantees survive server crashes, worker restarts, and distributed execution.
